# Phase 2 — Schema Requirements Traceability Matrix (Audited & Frozen)

This matrix maps all 25 system requirements directly to the 17 proposed database tables, identifying the required data attributes, target tables, underlying data sources, and storage modalities (Stored vs. Dynamically Derived).

| # | Project Requirement | Required Data | Required Table(s) | Required Column(s) | Source | Stored or Derived | Rationale / Viva Defense |
|---|---|---|---|---|---|---|---|
| **1** | **User registration & login** | Username, email, hashed credentials, full name | `users` | `id`, `username`, `email`, `password_hash`, `full_name`, `is_active` | System / Application | Stored | Fundamental user identification and credential verification. |
| **2** | **JWT authentication** | Token payload subjects, secret verification, last active time | `users` | `id`, `username`, `role`, `is_active`, `last_login_at` | Application Auth | Stored / Token runtime | Stateless JWT tokens generated dynamically from stored user records. |
| **3** | **Role-based access control** | Authorization level ('ADMIN', 'ANALYST', 'OFFICER') | `users` | `role` | Application Auth | Stored | Enforces RBAC permissions across API endpoints and UI views. |
| **4** | **Crime analytics** | Aggregated counts, frequencies, clearances, volumes | `crime_incidents`, `crime_types` | `id`, `incident_date`, `case_status`, `crime_type_id` | `crime_dataset_nationwide.csv` | Stored incidents; aggregations derived via SQL/Pandas | Dynamic OLAP aggregations derived from stored atomic crime events. |
| **5** | **Crime statistics** | Totals, clearance rate, victim age distribution, weapons | `crime_incidents`, `district_demographics` | `victim_age`, `victim_gender`, `weapon_used`, `case_status`, `total_population` | `crime_dataset_nationwide.csv`, `india-districts-census-2011.csv` | Stored; summary stats derived dynamically | Eliminates static pre-aggregated tables in favor of dynamic aggregation queries. |
| **6** | **Crime type analysis** | Incidents grouped by legal crime code and severity | `crime_types`, `crime_categories`, `crime_incidents` | `crime_types.crime_name`, `crime_categories.category_name`, `crime_types.severity_level` | `crime_dataset_nationwide.csv` | Stored (Severity is project-defined) | Normalizes crime taxonomy to enable cross-category comparative analytics. |
| **7** | **Location-wise crime analysis** | Crime distribution across State and District | `states`, `districts`, `crime_incidents` | `states.state_name`, `districts.district_name` | `crime_dataset_nationwide.csv` | Stored | Two-tiered normalized geography hierarchy enables drill-down analytics from National to District level. |
| **8** | **Time-wise crime analysis** | Incident occurrences by Year, Month, Day, and Hour | `crime_incidents` | `incident_date`, `incident_time` | `crime_dataset_nationwide.csv` | Stored; temporal bins derived in queries | Temporal indexing allows high-speed filtering across temporal dimensions. |
| **9** | **Crime prediction** | Forecasted crime volume for future dates by district | `crime_predictions`, `ml_models` | `prediction_date`, `predicted_crime_count`, `confidence_lower`, `confidence_upper` | ML Inference Pipeline | Stored (predictions) | Retains ML forecasting outputs for fast dashboard rendering without re-running models on page load. |
| **10** | **Future crime trend forecasting** | Multi-month forward trend trajectory | `crime_predictions`, `crime_risk_scores` | `predicted_crime_count`, `trend_index`, `period_year`, `period_month` | ML Inference Pipeline | Stored | Enables line charts displaying historical vs predicted trajectories. |
| **11** | **Crime Risk Score** | Composite district risk index (0-100) & risk tier | `crime_risk_scores` | `overall_risk_score`, `risk_level`, `severity_index`, `trend_index`, `volume_index` | Risk Engine Service | Stored | Pre-computed monthly composite score based on volume, severity, trend, and population. |
| **12** | **Crime-prone location identification** | High-risk and critical-tier district hotspots | `crime_risk_scores`, `districts` | `districts.district_name`, `overall_risk_score`, `risk_level` | Risk Engine Service | Stored / Filtered | Identifies geographic priority zones requiring emergency or proactive police intervention. |
| **13** | **Police/resource optimization** | Calculated resource quota matching predicted risk | `resource_recommendations` | `available_quantity`, `recommended_quantity`, `shortfall_quantity` | Optimization Service | Stored | Mathematical linear programming / heuristic balancing workload against available personnel. |
| **14** | **Resource recommendations** | Personnel & vehicle allocations by resource type | `resource_types`, `resource_recommendations` | `resource_types.resource_name`, `recommended_quantity`, `shortfall_quantity` | Optimization Service | Stored | Transparent operational recommendations presented to police station commanding officers. |
| **15** | **Budget estimation** | Projected operational cost for recommended resources | `budget_estimations`, `resource_costs` | `unit_cost`, `recommended_units`, `estimated_total_cost`, `currency` | Budget Service | Stored | Dynamic cost calculation (`recommended_units * unit_cost`) supporting fiscal planning. |
| **16** | **AI-generated recommendations & explanations** | Explainable justification for resource allocations | `resource_recommendations` | `optimization_rationale` | Decision Engine / LLM Service | Stored text | Provides non-blackbox explainability (e.g. why 5 extra patrol vehicles were assigned). |
| **17** | **Interactive charts** | Clean time-series, categorical distributions, radar | `crime_incidents`, `crime_predictions`, `crime_risk_scores` | Aggregated JSON payloads | FastAPI APIs | Derived from Stored Data | FastAPI endpoints transform stored records into structured Recharts format. |
| **18** | **District / State filtering** | Hierarchical cascading dropdown options | `states`, `districts` | `state_id`, `district_id` | Normalized Geography | Stored | Foreign-key linked geography ensures instant cascading filter performance. |
| **19** | **Map-based visualization** | Geographic coordinates & risk heatmaps | `districts`, `crime_risk_scores` | `census_district_code`, `district_name`, `overall_risk_score`, `risk_level` | Normalized Geography + Risk Engine + GeoJSON | Stored (Bound to GeoJSON) | Districts bind to standard India district boundary GeoJSON polygons via code/name for Leaflet maps. |
| **20** | **ML model training & evaluation** | Training records, feature matrix, validation splits | `crime_incidents`, `district_demographics` | Incident timestamps, categories, district population | MySQL Stored Data | Derived during ML Pipeline | Source data extracted from MySQL; feature engineering (lags, rolling stats) computed in memory. |
| **21** | **Prediction storage** | Audit trail of predictions with model lineage | `crime_predictions`, `ml_models` | `model_id`, `predicted_crime_count`, `generated_at` | ML Inference Engine | Stored | Connects predictions to the specific ML model version that created them. |
| **22** | **Model performance tracking** | Validation metrics history across training runs | `ml_models` | `version`, `algorithm`, `evaluation_metrics` (MAE, RMSE, R2), `is_active` | ML Training Pipeline | Stored | Empirically compares model performance before activating in production. |
| **23** | **PDF report generation** | Archival record of exported reports | `generated_reports` | `report_title`, `report_type`, `file_path`, `generated_at` | ReportLab Service | Stored metadata (PDF file on disk) | Preserves metadata of generated executive briefs without bloating MySQL with binary PDF files. |
| **24** | **Admin dashboard** | Management of costs, resource quotas, and users | `users`, `resource_costs`, `district_resources` | Admin management fields | Admin UI / API | Stored | Allows authorized administrators to tune system parameters and cost schedules. |
| **25** | **Audit / history where necessary** | Log of security events, configuration updates | `audit_logs` | `user_id`, `action`, `entity_type`, `entity_id`, `details`, `created_at` | Application Middleware | Stored | Transparent tracking of administrative actions for compliance and viva presentation. |
