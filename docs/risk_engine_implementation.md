## 2. Input Data & Lineage

The engine consumes strictly authentic project ground truth:
- **Historical Incidents**: $191,679$ incidents from `crime_incidents` (no synthetic data). Preceding 12 calendar months: `2025-01-01` to `2025-12-31`. Future predictions and 2026 data are strictly excluded.
- **Population Baseline**: Official Census 2011 baseline from `district_demographics` (`census_year = 2011`). Zero or non-positive population cases are explicitly guarded against.
- **Production Forecasts**: Genuine $1$-month ahead predictions from `crime_predictions` generated by active model `HGBR production forecasting model v1` (`version = 'v1.0.0'`, `model_id = 1`) for `forecast_period = '2026-01-01'`.
- **Assessment Scope**: Exactly $640$ historical administrative districts.

## 3. Mathematical Formula & Scoring (`risk-v1.0`)

$$\text{Overall Risk Score}_d = 0.30 \cdot F_{\text{pct}} + 0.20 \cdot V_{\text{pct}} + 0.30 \cdot R_{\text{pct}} + 0.20 \cdot T_{\text{pct}}$$

### Component Factor Formulations:
1. **Forecast Percentile ($F_{\text{pct}}$)**:
   Percentile rank of predicted crime count $\hat{y}_{d, \text{2026-01-01}}$ across the 640 districts.
2. **Historical Volume Percentile ($V_{\text{pct}}$)**:
   Percentile rank of trailing 12-month incident count ($2025$ calendar year).
3. **Crime Rate Percentile ($R_{\text{pct}}$)**:
   Percentile rank of annualized crime rate per $100,000$ Census 2011 population:
   $$R_d = \frac{V_d}{\text{Census2011Population}_d} \times 100{,}000$$
4. **Recent Trend Percentile ($T_{\text{pct}}$)**:
   Percentile rank of short-term acceleration ratio:
   $$T_d = \min\left(3.0, \frac{\text{Oct--Dec 2025 Volume}}{\text{Jul--Sep 2025 Volume} + 1.0}\right)$$
5. **Auxiliary Severity Index ($S_d$)**:
   Weighted average incident severity across 2025 incidents:
   $$\text{Severity Index}_d = \frac{\sum w_{\text{cat}}}{N_d}$$
   *(Violent: 1.5, Fire: 1.2, Traffic: 1.1, Other: 1.0). Retained exclusively for operational audits; 0% weight in composite score.*

### Risk Band Thresholds:
- **LOW**: $0.00 \le \text{Score} < 35.00$
- **MODERATE**: $35.00 \le \text{Score} < 50.00$
- **HIGH**: $50.00 \le \text{Score} < 65.00$
- **CRITICAL**: $65.00 \le \text{Score} \le 100.00$

## 4. Database Schema & Idempotence

### Table: `crime_risk_scores`
```sql
CREATE TABLE `crime_risk_scores` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `district_id` int NOT NULL,
  `period_year` smallint NOT NULL,
  `period_month` smallint NOT NULL,
  `overall_risk_score` decimal(5,2) NOT NULL,
  `risk_level` enum('LOW','MODERATE','HIGH','CRITICAL') NOT NULL,
  `severity_index` decimal(5,2) NOT NULL,
  `trend_index` decimal(5,2) NOT NULL,
  `volume_index` decimal(5,2) NOT NULL,
  `forecast_index` decimal(5,2) DEFAULT NULL,
  `rate_index` decimal(5,2) DEFAULT NULL,
  `model_id` int DEFAULT NULL,
  `model_version` varchar(20) DEFAULT NULL,
  `factor_contributions` json DEFAULT NULL,
  `strongest_driver` varchar(50) DEFAULT NULL,
  `population_density_factor` decimal(5,2) NOT NULL,
  `calculation_version` varchar(20) NOT NULL,
  `generated_at` timestamp NOT NULL DEFAULT (now()),
  PRIMARY KEY (`id`),
  UNIQUE KEY `uq_district_risk_period_version` (`district_id`,`period_year`,`period_month`,`calculation_version`),
  KEY `idx_risk_period` (`period_year`,`period_month`,`overall_risk_score`),
  KEY `fk_risk_model` (`model_id`),
  CONSTRAINT `crime_risk_scores_ibfk_1` FOREIGN KEY (`district_id`) REFERENCES `districts` (`id`) ON DELETE RESTRICT,
  CONSTRAINT `fk_risk_model` FOREIGN KEY (`model_id`) REFERENCES `ml_models` (`id`) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### Idempotence Mechanism:
- Enforced via unique constraint `(district_id, period_year, period_month, calculation_version)`.
- Re-running the pipeline executes `ON DUPLICATE KEY UPDATE`, updating values in place without inflating row counts.
- Verified programmatically: Run 1 yielded $640$ rows; Run 2 yielded exactly $640$ rows ($0$ duplicates).

## 5. API Endpoints

All endpoints require standard Bearer JWT authorization (`Authorization: Bearer <token>`):

1. **`GET /api/v1/risk/overview`**:
   - Query Parameters: `assessment_period` (default `2026-01-01`), `calculation_version` (default `risk-v1.0`).
   - Returns: Assessed district count, mean/median/min/max risk score, risk band distribution counts and percentages, top critical districts, and active model provenance.
2. **`GET /api/v1/risk/model`**:
   - Returns: Frozen `risk-v1.0` methodology specification, factor definitions, weights, and linked production model metadata.
3. **`GET /api/v1/risk`**:
   - Query Parameters: `state_id`, `district_id`, `risk_level`, `assessment_period`, `calculation_version`, `skip`, `limit`.
   - Returns: Paginated list of assessed district risk scores.
4. **`GET /api/v1/risk/{district_id}`**:
   - Path Parameter: `district_id`.
   - Returns: Comprehensive explainability object detailing raw metrics, factor percentiles, weighted contributions, and the `strongest_driver`.

## 7. Known Limitations & Scope Boundaries

1. **Scope Boundaries**: This module strictly provides Risk Scoring, Categorization, and Explainability. It does **not** generate police deployment rosters, patrol quotas, or budgetary allocations. Those actions will be handled by the Resource Optimization module in later phases.
2. **Population Data**: Per-capita rates reflect Census 2011 baseline figures; post-2011 demographic shifts are accounted for via recent trend acceleration ($T_d$) and machine learning volume forecasts ($F_d$).
3. **Granularity**: The current evaluation is conducted at the District $\times$ Month panel level; subdivision/police-station level assessments are reserved for future localized extensions.
